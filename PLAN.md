# План работ — mpgd

Адаптер USB-HID пульта **XHC LHB04** (и клонов, напр. KTURT) ↔ **PlanetCNC TNG**
(контроллеры Mk3/4). Демон читает кнопки и маховик, джогает оси, обновляет
LCD пульта и обрабатывает кнопки по YAML-конфигу.

Дата последнего обновления: 2026-08-15

---

## Текущий статус

Основной функционал v1 реализован и собирается под Windows; проверен на реальном
пульте (клон KTURT, 6-байтовые пакеты) вместе с обратной связью на LCD. Остались
валидация на реальном контроллере PlanetCNC, приёмка и перенос на Linux.

## Дальнейшие работы

### Этап 3 — Валидация на реальном контроллере

Прогресс: добавлена диагностическая утилита `tng_probe` (`tools/tng_probe/`)
для опроса TNG API на реальном контроллере: `status` / `params` / `commands`
(только чтение, безопасно) и `jog` (двигает оси, только in-process). Собран
`PlanetCNCLib64.dll` ver=20251124; контроллер опрошен в attach-режиме.

- [x] Уточнить семантику `Jog(step, x, y, z)` на Mk3/4. Подтверждено на
      реальном контроллере (in-process, `tng_probe jog`/`move`):
      - **Step** (`step=true`): величина `x/y/z` **игнорируется**, ось
        двигается ровно на параметр `_jog_step` (мм), направление = знак.
        Движение рывковое (мгновенный скачок на макс. ускорении).
      - **Continuous** (`step=false`): `x/y/z` — скорость в **мм/с**.
      - **MoveAxis(speed, axis, target)** — плавный переезд к **абсолютной**
        координате. Скорость: значение/10 = мм/мин (проверено: `speed=1000` →
        ~100 мм/мин). Это подходящий примитив для позиционного режима.
      - Джог/перемещение возвращают `ok`, но не двигают ось при выключенных
        моторах — нужен `M10 P1` (Motors Enable).
      **Колесо переведено на позиционный режим** (по отзыву пользователя:
      пошаговый джог пропускает шаги и дёргается): `JogController` накапливает
      целевую координату и едет к ней через `MoveAxis`; `main.cpp` — Run в
      отдельном потоке + `M10 P1`. Юнит-тесты обновлены.
- [x] Подтвердить имена параметров скорости джога и override-параметров.
      Через `GetParam` на реальном контроллере: `_ovrd_speedfeed` (подача),
      `_ovrd_spindle` (шпиндель), `_ovrd_speedtraverse`; старые имена
      `SpeedFeedOverride` / `SpeedSpindleOverride` возвращают NaN. Конфиг и
      значения по умолчанию исправлены на `_ovrd_speedfeed` / `_ovrd_spindle`
      (1.0 = 100%).
- [x] Подтвердить таблицу кодов кнопок на конкретном экземпляре пульта.
      Пульт — клон KTURT (6-байтовые пакеты, две HID-коллекции). Проверено
      вручную через `mpg_gui`: кнопки именуются корректно, т.е. таблица кодов
      в `XhcProtocol.h` (18-button layout2) совпадает с этим пультом.
      `mpgd --sniff` остаётся для диагностики нестандартных кодов.

Прочие находки этапа 3:

- [x] Загрузка DLL: `PlanetCNCLib64.dll` зависит от `PlanetCNCCore64.dll`
      (в той же папке). `TngApi::loadLibrary` теперь использует
      `LOAD_WITH_ALTERED_SEARCH_PATH`, чтобы полный путь работал без правки PATH.
- [x] `Run()` **блокирует** (крутит цикл сообщений TNG на вызывающем потоке
      до `Exit()`). `TngApi::run/runProfile/exit/exitForce` больше не держат
      mutex (иначе дедлок всех прочих вызовов API); даемон запускает `Run()`
      в отдельном потоке.
- [x] In-process требует прав администратора (контроллер через libusbK;
      у `PlanetCNC64.exe` манифест `highestAvailable`). Даемон в реальной
      эксплуатации тоже должен запускаться elevated.
- [ ] `GetCmdId` в attach-режиме возвращает 0 для всех имён (включая
      заведомо неверные) — резолв именованных команд через pipe не работает.
      Именованные кнопки (home_all, set_work_zero, spindle_toggle, ...) в
      attach-режиме могут не срабатывать; проверить in-process.
- [ ] `InfoWorkPosition3` in-process возвращает NaN до привязки/сброса
      рабочей позиции; моторная позиция читается корректно. Для LCD рабочие
      координаты нуждаются в хоминге/установке нуля.
- [ ] Мягкие лимиты: контроллер ограничивает ход (~394.4 мм по X) — джог
      упирается в лимит и останавливается.
- [ ] `_jog_round` (0.1 мм) округляет позицию после джога; для шагов < 0.1 мм
      нужна отдельная проверка точности (AC-01).
