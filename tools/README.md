# tools — вспомогательные утилиты

Диагностические и сервисные инструменты проекта `mpgd`, не входящие в состав
основного демона. Собираются вместе с проектом через CMake и не влияют на
`mpgd` и unit-тесты.

| Утилита | Путь | Назначение |
|---|---|---|
| `mpg_gui` | `tools/mpg_gui/` | GUI для проверки пульта XHC LHB04 и совместимых клонов (KTURT): чтение сырых HID-пакетов и наглядное отображение кнопок, селектора осей и маховика |

---

## mpg_gui — тестовый GUI адаптера

Оконное приложение (Dear ImGui + Win32 + OpenGL3), которое **напрямую**
открывает USB-HID устройство **XHC LHB04** или совместимый клон **KTURT**
(VID `0x10CE`, PID `0xEB70`/`0xEB71`/`0xEB93`) и в реальном времени показывает
всё, что происходит на пульте. Предназначено для проверки работы адаптера:
крутите маховик, поворачивайте ручку выбора оси, нажимайте кнопки — изменения
сразу отображаются на экране.

В отличие от демона `mpgd`, утилита:

- **не** загружает PlanetCNC TNG и **не** выполняет никаких команд станка;
- показывает **сырое** состояние пульта — без edge-детекции кнопок, debounce
  и без сопоставления кнопок с действиями из YAML (кроме лёгкой фильтрации
  дребезга только в журнале событий);
- работает даже когда TNG не установлен / не запущен.

Поэтому дребезг контактов кнопок и «лишние» импульсы маховика в журнале —
это нормальное поведение инструмента: его задача показать физический отклик
адаптера, а не «чистое» состояние для джога.

### Возможности

- **Статус подключения** — цветной индикатор `CONNECTED` / `DISCONNECTED`,
  имя производителя и продукта устройства; автоматическое подключение при
  вставке кабеля и отображение потери связи.
- **Сырой отчёт** — байты входящего HID-пакета (report `0x04`) в hex с
  указанием фактической длины (6 или 8 байт); каждый пакет попадает в журнал
  (троттлинг ~2/с при неизменном содержимом).
- **Захват в файл** — каждый принятый пакет целиком дописывается в
  `mpg_gui_raw.log` (в рабочей папке) без троттлинга; путь показан в окне
  журнала.
- **Расшифровка полей** — report ID, кнопка 1, кнопка 2, код селектора оси,
  дельта маховика, feed-ротатор, seed и контрольная сумма (только у
  8-байтовых отчётов, статус `OK`/`MISMATCH`), признак «сна», счётчики
  пакетов и ошибок чексуммы, накопленные импульсы маховика.
- **Селектор оси** — наглядная подсветка текущего положения ручки
  (`OFF`/`X`/`Y`/`Z`/`A`/`Spindle`/`Feed`).
- **Маховик (MPG)** — накопленное число импульсов и последняя дельта с
  указанием направления (`clockwise (+)` / `counter-clockwise (-)`).
- **Обратная связь (дисплей пульта)** — шесть независимых переменных
  `X/Y/Z/A/S/F`, накапливаемых от маховика: колёсико меняет только ту
  переменную, на которую указывает ручка выбора оси. Состояние отправляется
  на LCD пульта исходящими feature-отчётами `0x06` (~25 Гц), поэтому дисплей
  больше не в нулях; `X/Y/Z` — три рабочие строки, `A` — первая строка при
  выборе A, `S/F` — проценты override. На Windows пульт перечисляется как
  несколько HID-коллекций (вход и дисплей — разные device-узлы), поэтому
  утилита пробует узлы feature-отчётом и открывает вход/дисплей отдельно.
- **Кнопка** — имя и код нажатой в данный момент кнопки.
- **Журнал событий** — отметки времени: сырые пакеты, нажатия/отпускания
  кнопок, импульсы маховика (троттлинг ~10/с), подключения/отключения,
  ошибки чтения и простои устройства (`no input reports`).
- **Копирование** — кнопки `Copy raw` (текущий отчёт) и `Copy log` (весь
  журнал) кладут текст в буфер обмена.
- **Сброс счётчиков** и **очистка журнала** кнопками в UI.

### Сборка

Утилита собирается как отдельная цель CMake и тянет Dear ImGui через
`FetchContent` (первая сборка требует доступа в интернет):

```powershell
cmake -S . -B build -G "Visual Studio 17 2022" -A x64
cmake --build build --config Release --target mpg_gui
```

Результат — `build/Release/mpg_gui.exe` (самодостаточный, консольное окно не
открывается).

> Примечание: Dear ImGui v1.90.9 не содержит корневого `CMakeLists.txt`,
> поэтому в `CMakeLists.txt` проекта библиотека `imgui` собирается вручную из
> исходников (`imgui.cpp`, `imgui_draw.cpp`, `imgui_tables.cpp`,
> `imgui_widgets.cpp`).

### Запуск

```powershell
build\Release\mpg_gui.exe
```

Порядок действий для проверки адаптера:

1. Подключите пульт к USB и запустите `mpg_gui.exe`.
2. Убедитесь, что в заголовке окна появился `CONNECTED` с именем устройства.
3. Повращайте маховик — в блоке «MPG wheel» должна меняться дельта и
   накопленный счётчик, направление зависит от стороны вращения.
4. Поверните ручку выбора оси — подсветится активная позиция, в таблице
   полей обновится код селектора.
5. Поочерёдно нажмите все кнопки — имя кнопки появится в блоке «Button», а
   в журнале событий зафиксируются нажатие и отпускание.
6. Отключите и снова подключите USB — приложение должно показать
   `DISCONNECTED`, затем автоматически переподключиться.

### Окна приложения

**«MPG adapter test»** — сводка состояния:

- заголовок с индикатором подключения и VID/PID;
- строка сырого отчёта с указанием длины (моноширинным шрифтом) и кнопкой
  `Copy raw`;
- таблица «поле → значение»;
- подсветка активной позиции селектора осей;
- блоки «MPG wheel» и «Button»;
- кнопка `Reset counters`.

**«Event log»** — журнал событий с отметками времени, кнопками `Clear` и
`Copy log`, строкой пути к файлу полного захвата (`mpg_gui_raw.log`).
Автопрокрутка вниз, если вы находитесь у нижней границы списка.

### Принцип работы

Приложение состоит из двух потоков:

1. **Поток чтения** (`readerThread`) — в цикле:
   - открывает устройство через `mpgd::usb::HidDevice` (повторные попытки
     каждые 2 с, пока пульт не подключён); на Windows перечисляет HID-узлы,
     пробует их feature-отчётом и открывает узел входа и узел дисплея
     отдельно;
   - блокирующее чтение отчёта в буфер 64 байта с таймаутом 50 мс (фактическая
     длина — 6 или 8 байт в зависимости от устройства);
   - разбор через `mpgd::usb::PacketParser::parseInput` (для 6-байтовых —
     best-effort без seed/чексуммы);
   - запись каждого сырого пакета в файл `mpg_gui_raw.log`;
   - запись последнего состояния в общий `Snapshot` под mutex;
   - добавление событий в журнал (кнопки — с фильтром дребезга 15 мс,
     маховик и сырые пакеты — с троттлингом);
   - отправка на дисплей пульта исходящих feature-отчётов `0x06`
     (`PacketParser::buildDisplayPayload`, троттлинг ~40 мс).
2. **Поток UI** — главный цикл Win32 + OpenGL3: отрисовка окон ImGui,
   копирование `Snapshot` и журнала под mutex, ограничение ~60 FPS.

Переиспользуются классы ядра проекта (`mpgd::usb::HidDevice`,
`mpgd::usb::PacketParser`, `mpgd::xhc::*`), поэтому утилита гарантированно
читает тот же протокол, что и демон. Любая длина отчёта > 0 обрабатывается
как данные; разрыв соединения происходит только при ошибке hidapi (`r < 0`).

### Протокол (справочно)

Входящий пакет — report ID `0x04`. Эталонное устройство XHC шлёт **8 байт**,
совместимые клоны (например, KTURT) — **6 байт** (без seed и чексуммы). Обе
длины поддерживаются:

| Байт | Поле | Показывается как |
|---|---|---|
| 0 | Report ID (`0x04`) | `Report ID` |
| 1 | Код нажатой кнопки (`0x00` — нет) | `Button 1` |
| 2 | Вторичная кнопка | `Button 2` |
| 3 | Положение ручки выбора оси | `Axis selector` |
| 4 | Дельта маховика (int8, −128…+127) | `Jog delta` |
| 5 | Feed/шаговый ротатор (у KTURT — дубль кнопки) | `Feed rotary` |
| 6 | Seed (только у XHC) | `Seed` |
| 7 | Чексумма, XOR байтов 1–6 (только у XHC) | `Checksum` |

Положения ручки: `OFF=0x00`, `X=0x11`, `Y=0x12`, `Z=0x13`, `Spindle=0x14`,
`Feed=0x15`, `A=0x18`.

Коды кнопок (18-кнопочный пульт, раскладка `xhc-hb04-layout2`):

| Код | Кнопка | Код | Кнопка |
|---|---|---|---|
| 0x01 | `goto_zero` | 0x0D | `step` |
| 0x02 | `start_pause` | 0x0E | `mode` |
| 0x03 | `rewind` | 0x0F | `macro_6` |
| 0x04 | `probe_z` | 0x10 | `macro_7` |
| 0x05 | `macro_3` | 0x16 | `stop` |
| 0x06 | `half` | 0x17 | `reset` |
| 0x07 | `zero` | 0x08 | `safe_z` |
| 0x09 | `home` | 0x0C | `spindle` |
| 0x0A | `macro_1` | 0x0B | `macro_2` |

Неизвестный код кнопки отображается как `0xXX` (hex) — полезно при проверке
на конкретном экземпляре пульта, см. замечание о расхождениях в
[основном README](../README.md).

### Замечания

- **Чексумма**: у 6-байтовых клонов (KTURT) чексуммы и seed нет вовсе — поля
  `Seed` и `Checksum` показывают `-`. У 8-байтовых отчётов эталонный драйвер
  LinuxCNC `xhc-hb04` чексумму не проверяет, поэтому `MISMATCH` не обязательно
  означает неисправность: значение вычисляется как XOR байтов 1–6 и может
  отличаться на конкретном устройстве.
- **Простой устройства**: пульт шлёт пакеты только при активности
  (кнопка/маховик/ручка). Когда ничего не происходит, в журнале раз в секунду
  появляется `no input reports (read timeout)` — это штатное поведение, а не
  обрыв связи.
- **«Сон» пульта**: если все поля пакета нулевые, пульт считается спящим
  (`Sleeping: yes`).
- **Несколько устройств**: открывается первое подходящее устройство с VID
  `0x10CE` и одним из PID `0xEB70`/`0xEB71`/`0xEB93`.
- Для захвата пакетов в консоль без GUI по-прежнему доступен режим демона:
  `mpgd --sniff` (логирует сырые hex-дампы через spdlog).
